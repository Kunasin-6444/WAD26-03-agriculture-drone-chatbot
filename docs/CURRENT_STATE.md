## สรุปสถานะ — Gemini / ตอบใหม่ทุกคำถาม / URL ตรงแหล่ง — 1 พ.ย. 2026

- ตามคำสั่งเจ้าของรอบนี้เปลี่ยน `RAG_MODEL` ใน `.env` เป็น `gemini-3.7-flash` พร้อม `.env.example` และค่าเริ่มต้นของ generation; ตรวจ config ใน process ใหม่ว่าเลือก Gemini เป็นตัวแรกแล้ว ไม่มี API call การตั้ง fallback เดิมยังอยู่ จึงไม่ใช่การล็อกว่า Gemini เท่านั้นทุกกรณี
- ถอดแคชคำตอบและ in-flight coalescing ออกจาก `ai_service.ask_ai` ทุกคำถามใหม่รวมข้อความเหมือนเดิม/พร้อมกันเข้าสู่ pipeline ใหม่ ยังคง Rich menu/Flex สำเร็จรูปตามเดิม SQLite inbox ใช้ event ID กัน webhook เดิมซ้ำและเก็บงานส่ง ไม่ใช่แคชถาม–ตอบตามข้อความ ไม่ลบฐานข้อมูลหรือคิวค้าง
- URL อ้างอิงเก็บจากหน้าใน evidence ถึงข้อความ LINE ครบ path/query/fragment ไม่ย่อเป็นโดเมน; เอาลิงก์ homepage ที่เติมอัตโนมัติในหมายเหตุ CAAT ออก ตรวจด้วย fixture ผ่าน search-result → evidence → renderer → LINE payload และไม่อ้างหน้าอื่นที่ไม่ได้ใช้
- ตรวจ offline 115 tests + 34 subtests ในส่วน fresh answers, citations, natural renderer, availability, question focus, LINE inbox/menu ผ่านหลังแก้ตำแหน่ง assertion ของเทสต์ใหม่และทวนเฉพาะ 2 เคสที่เกี่ยวข้อง ไม่มี live/API เพิ่ม ไม่ใช้ผลนี้ยืนยันความแม่น/ความคงเส้นคงวาของ Gemini
- แทน `test_answer_cache_contract.py` ที่รับรองพฤติกรรม cache เก่าด้วย `test_fresh_answers.py`; ตัดเทสต์รอ shared future ที่เลิกใช้ เก็บและทดสอบการกัน LINE redelivery, ค่าผิด/แถวผิดและแหล่งผิดตามเดิม
- ยังไม่ได้ restart service/rebuild container ที่อาจเปิดอยู่ ต้องเริ่ม process ใหม่หรือ build/recreate Docker จึงโหลดโค้ดและ config นี้ งานค้าง u03/เว็บ DJI/เนื้อหาเมนู 4–6 ยังไม่ถูกแก้ในรอบนี้

  1. **KB-First RAG:** ค้นเอกสารในคลังความรู้ก่อน (กรองเอกสารโดรนสำรวจออกเมื่อไม่ได้ถามเรื่องสำรวจ/ภาพถ่าย และดึงตารางต่อเนื่องข้ามหลายหน้าครบ เช่น ตารางที่ 4 หน้า 10–14)
  2. **Auto Web Fallback (แยกขาดจาก KB):** หากคลังเอกสารไม่มีคำตอบ (`NOT_FOUND` หรือไม่พบข้อมูลรุ่น/เรื่องที่ถามในเอกสาร) ระบบจะสลับไปค้นอินเทอร์เน็ต (`web_fallback` / `caat_portal`) และส่งเฉพาะหลักฐานจากเว็บให้โมเดลตอบโดยไม่ผสมกับ KB
  3. **ปฏิเสธคำถามลูกผสม (Strict Mixed-Question Rejection):** คำถามที่ผูกเวลาปัจจุบันเข้ากับตารางคำแนะนำในเอกสาร (เช่น `"ปลูกอ้อยตั้งแต่เดือนมกราคม จนถึงเดือนนี้ ตอนนี้ต้องพ่นอะไร"`) หรือถามควบเรื่องในเอกสารกับราคาเว็บในข้อเดียวกัน ระบบปฏิเสธทันที (`source_type = "abstain"`, 0 วินาที, 0 LLM calls) พร้อมแจ้งให้ผู้ใช้ระบุอายุพืช/ระยะเจริญเติบโตโดยตรงหรือแยกถามทีละหัวข้อ
- ผลทดสอบสด 12 เคส (KB 7, Web 2, KB→Web Fallback 1, Mixed Abstain 2) ด้วย `gemini-3.7-flash` ผ่านครบ **12/12 (100.0%)** เวลาตอบเฉลี่ยรวม **5.82 วินาที** (KB เฉลี่ย **7.08 วินาที**, Web/Fallback เฉลี่ย **6.75 วินาที**, ราคาน้ำมันทางการ **1.71 วินาที**, ปฏิเสธคำถามลูกผสม **0.00 วินาที**) [ผลเต็ม](../cache/eval/final_nonframework_live_20261031/results_v2.json); เทสต์ออฟไลน์ผ่านครบ 839 passed

  "สูงแค่ไหน เร็วแค่ไหน" ตอบ 2 m / 1, 2, 4 m/s ซึ่งเป็นเงื่อนไขการทดสอบ (UAV06 หน้า 10) → กฎ prompt ค่าทดสอบห้ามเขียนเป็นค่าแนะนำ (ลองสดแล้วถูก);
  คำถามต่อเนื่อง: `ai_service.previous_question` จำคำถามเต็มล่าสุดต่อ user_id (LINE) 10 นาที (`CONVERSATION_TTL_SECONDS`);
  ข้อความ ≤30 ตัวอักษร (`FOLLOW_UP_MAX_CHARS`) ค้น 2 รอบ (คำถามใหม่อย่างเดียว + รวมหัวเรื่อง) แล้วสลับรวม (`interleave_evidence`)
  และส่ง previous_question ให้โมเดล ไม่ใช้ cache; prompt: ห้ามตอบเรื่องใกล้เคียงแทน, คำถามกว้างให้ "ถามกลับ:" พร้อมหัวข้อ (ระบบแสดงเฉพาะบรรทัดไม่มีตัวเลข)
  เล่นบทสนทนาซ้ำบน deepseek: "สูงแค่ไหน เร็วแค่ไหน" รู้บริบทและบอกว่าเป็นค่าทดสอบ; ผลบางข้อยังแกว่งตามโมเดล (deepseek ช้า/ไม่คงที่)

### ตรวจโค้ดความพร้อมใช้งานจริง 2026-10-19 (Codex)

ขอบเขตล่าสุด: เจ้าของใช้เอง ถามไม่เยอะ ใช้บริการมหาวิทยาลัยไปก่อน และยังไม่ต้องสน billing โครงสร้างรองรับการใช้ส่วนตัวเมื่อโควตาพร้อม; billing/เพดานคิว/production host ไม่ใช่งานเร่งด่วน เน้นความถูกต้องของคำตอบและการแจ้งเมื่อบริการใช้ไม่ได้

ผลตรวจรอบก่อนในวันเดียวกัน: อ่านโค้ดและตรวจ offline โดยไม่เรียก provider หรือเปิดฐานจริง; **88 focused tests และ 22 subtests ผ่าน**, `pip check` ผ่าน (ไม่ใช่ full suite หรือคะแนนคุณภาพคำตอบ) รอบปรับขอบเขตนี้แก้เฉพาะเอกสาร ไม่รัน tests/API เพิ่ม

**งานที่ลงมือหลังเจ้าของอนุมัติในวันเดียวกัน:** แก้ A05–A06 แล้วตามขอบเขต offline

- แยกผลไม่มีหลักฐานจากโควตาหมด, rate limit, timeout, สิทธิ์ถูกปฏิเสธ, config ไม่ครบ และบริการขัดข้อง; KKU daily-limit 401 ไม่แสดงเป็นคีย์เสีย ข้อความผิดพลาดไม่เผยรายละเอียด provider/secret
- ใช้สถานะ cooldown ที่ทราบอยู่ตรวจทั้ง primary/fallback/secondary ก่อนเริ่ม retrieval และก่อนค้น web; เมื่อไม่มีโมเดลที่เรียกต่อได้หยุดงานภายนอก แต่ cache และ bot usage ยังทำงาน หากมีโมเดลทางเลือกหรือ cooldown หมดอายุยังตอบตามปกติ
- เก็บ claims/อ้างอิง KB ที่ผ่านแล้วเมื่อขั้น web/LLM ถัดไปล้ม พร้อมแจ้งเหตุ; playground ส่ง HTTP 503 พร้อมรหัสเหตุสำหรับคำตอบที่ทำไม่ได้ทั้งคำถาม แต่ยังแสดงคำตอบบางส่วนได้; evaluator รู้จักข้อความขัดข้องใหม่
- ตรวจชุดหลัก **106 tests + 36 subtests ผ่าน**; หลังปรับกรณีเพิ่มเติม ตรวจชุดที่กระทบพร้อม LINE integration **53 tests + 22 subtests ผ่าน** (ชุดทับซ้อนกัน ไม่ใช่ผลรวมข้อไม่ซ้ำ); มี deprecation warning เดิม 1 รายการ ไม่รัน full suite หรือ live/API

ข้อจำกัด: cooldown เป็นความจำใน process จากข้อผิดพลาดที่เคยพบ ไม่ใช่การเช็ค quota สดหรือรู้เวลาที่ provider reset จริง; นโยบายลองใหม่เมื่อทุกโมเดลติด transient cooldown ระยะสั้นยังคงเดิม ต้อง restart playground/บริการที่เปิดไว้เพื่อโหลดโค้ดใหม่
