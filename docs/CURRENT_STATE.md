## ตรวจโค้ดความพร้อมใช้งานจริง 2026-10-19 (Codex)

ขอบเขตล่าสุด: เจ้าของใช้เอง ถามไม่เยอะ ใช้บริการมหาวิทยาลัยไปก่อน และยังไม่ต้องสน billing โครงสร้างรองรับการใช้ส่วนตัวเมื่อโควตาพร้อม; billing/เพดานคิว/production host ไม่ใช่งานเร่งด่วน เน้นความถูกต้องของคำตอบและการแจ้งเมื่อบริการใช้ไม่ได้

ผลตรวจรอบก่อนในวันเดียวกัน: อ่านโค้ดและตรวจ offline โดยไม่เรียก provider หรือเปิดฐานจริง; **88 focused tests และ 22 subtests ผ่าน**, `pip check` ผ่าน (ไม่ใช่ full suite หรือคะแนนคุณภาพคำตอบ) รอบปรับขอบเขตนี้แก้เฉพาะเอกสาร ไม่รัน tests/API เพิ่ม

**งานที่ลงมือหลังเจ้าของอนุมัติในวันเดียวกัน:** แก้ A05–A06 แล้วตามขอบเขต offline

- แยกผลไม่มีหลักฐานจากโควตาหมด, rate limit, timeout, สิทธิ์ถูกปฏิเสธ, config ไม่ครบ และบริการขัดข้อง; KKU daily-limit 401 ไม่แสดงเป็นคีย์เสีย ข้อความผิดพลาดไม่เผยรายละเอียด provider/secret
- ใช้สถานะ cooldown ที่ทราบอยู่ตรวจทั้ง primary/fallback/secondary ก่อนเริ่ม retrieval และก่อนค้น web; เมื่อไม่มีโมเดลที่เรียกต่อได้หยุดงานภายนอก แต่ cache และ bot usage ยังทำงาน หากมีโมเดลทางเลือกหรือ cooldown หมดอายุยังตอบตามปกติ
- เก็บ claims/อ้างอิง KB ที่ผ่านแล้วเมื่อขั้น web/LLM ถัดไปล้ม พร้อมแจ้งเหตุ; playground ส่ง HTTP 503 พร้อมรหัสเหตุสำหรับคำตอบที่ทำไม่ได้ทั้งคำถาม แต่ยังแสดงคำตอบบางส่วนได้; evaluator รู้จักข้อความขัดข้องใหม่
- ตรวจชุดหลัก **106 tests + 36 subtests ผ่าน**; หลังปรับกรณีเพิ่มเติม ตรวจชุดที่กระทบพร้อม LINE integration **53 tests + 22 subtests ผ่าน** (ชุดทับซ้อนกัน ไม่ใช่ผลรวมข้อไม่ซ้ำ); มี deprecation warning เดิม 1 รายการ ไม่รัน full suite หรือ live/API

ข้อจำกัด: cooldown เป็นความจำใน process จากข้อผิดพลาดที่เคยพบ ไม่ใช่การเช็ค quota สดหรือรู้เวลาที่ provider reset จริง; นโยบายลองใหม่เมื่อทุกโมเดลติด transient cooldown ระยะสั้นยังคงเดิม ต้อง restart playground/บริการที่เปิดไว้เพื่อโหลดโค้ดใหม่

ยังไม่แก้: intro ไม่ตรวจหลักฐาน, claim กลับความหมายบางแบบยังผ่าน, freshness ไม่ครอบคลุม “ตอนนี้” และ KB ยังพึ่ง Google embedding ก่อน BM25 คุณภาพคำตอบจริงยังต้องวัดเมื่ออนุมัติและโควตาพร้อม ข้อสังเกตเรื่อง answer secondary ไป Google และเพดานคิวเก็บไว้ในรายงาน ไม่ใช้เป็นเหตุขวางการใช้ส่วนตัวตามขอบเขตล่าสุด
