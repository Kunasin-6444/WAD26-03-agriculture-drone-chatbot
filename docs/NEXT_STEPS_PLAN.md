     ลองสดรอบสอง (เจ้าของ): โมเดลรวมสาร "ใบแคบและกว้าง" ไว้ใต้ป้าย "ใบแคบ" และตัวตรวจปล่อยผ่าน เพราะเช็คประเภทวัชพืชรวมทั้งข้อ (มีแถวใบแคบแถวเดียวก็ผ่าน)
     แก้ตัวตรวจแล้ว (`table_grounding`): ป้ายประเภทต้องตรงกับทุกแถวที่ป้ายนั้นครอบคลุม, ชื่อสารผสมไม่ถูกอ่านเป็นแถวสารเดี่ยว, ประโยคอธิบายส่วนผสมผ่าน แต่ใส่อัตราผิดให้สารเดี่ยวถูกจับ (เทสต์ใหม่ 4 ข้อ, ลองปิดแต่ละส่วนแล้วเทสต์จับได้)
     หมายเหตุปรึกษาผู้เชี่ยวชาญใช้ป้ายระดับเอกสาร `app/rag/document_topics.json` (แก้ได้ ไม่ต้อง ingest ใหม่ มีเทสต์กันชื่อเอกสารผิด) + อัตราสารในคำตอบ แทนการเดาจากชื่อไฟล์
  3. ข้อมูลคนละบริบทปนมา: คำถามแบต "กี่ % ขณะบิน" มี "ไม่ต่ำกว่า 25.0 V" ของโดรนสำรวจติดมา
  4. ถามต่อโดยไม่ระบุพืชได้คำตอบผิดเรื่อง เพราะไม่มีความจำบทสนทนา (พักไว้ตามคำสั่งเจ้าของ)
- ตรวจเฉพาะเส้นทางที่แก้ด้วยข้อมูลบันทึกหรือ stub แล้ววัดด้วยชุดข้อ 1 ไม่เปิด live batch อัตโนมัติ

## 3. ข้อมูลและ ingestion — ทำเมื่อ Vision quota กลับมา

- ~~ล้างขยะ UAV06 หน้า 5, 17 / UAV10 หน้า 40~~ เสร็จ 2026-10-19 `verify_ingestion` ผ่าน แต่ตารางจากภาพ UAV06 หน้า 5 หายไปด้วย (รายละเอียดและทางเลือกใน [CURRENT_STATE](CURRENT_STATE.md) ข้อ 5) รอเจ้าของเลือกว่าจะคืนหรือไม่

- เมื่อพบชื่อสาร/ตัวเลขที่ Vision อ่านผิดในคำตอบ ให้เก็บเป็นหลักฐานเพื่อตัดสินว่าจะให้ข้อความในไฟล์หรือ Vision เป็นหลักเมื่ออ่านซ้ำกัน

## 4. หลังมีตัวเลขจากชุดวัดผล

- ทดลอง reranker (ขั้นตอบ) และช่องค้นหาจากภาพหน้า PDF (embedding ทั้งหน้า) เป็นทางเลือก เก็บเฉพาะที่ดีขึ้นจริงและไม่ช้าเกินเป้า
- เมื่อมี host จึงทำ HTTPS, volumes/restore และ LINE end-to-end ตาม [DEPLOYMENT](DEPLOYMENT.md)
- full regression และ release verification ทำตามความเสี่ยงรวมของรุ่น ไม่เป็น gate ก่อนทดลองในเครื่อง

## ยังไม่ทำ

ไม่แข่ง Direct PDF vs RAG แบบแทนที่กัน, ไม่ re-ingest ทั้งคลังอัตโนมัติ, ไม่ทำความจำบทสนทนาจนกว่าเจ้าของสั่ง, ไม่เพิ่ม framework/ฐานข้อมูลโดยไม่มีปัญหาที่ต้องแก้
ไม่สร้างแผนหรือรายงานสถานะคู่ขนานอีก หากต้อง overhaul โค้ด ให้ทำเพื่อแก้ปัญหาที่สังเกตได้และรักษาข้อมูลให้ย้อนกลับได้
